## 三十一、診斷包判讀與自動隔離（v20260822e，2026-10-26）

使用者貼回的診斷包（主機：8 核／16GB／Chrome 155，localStorage 2.9MB，100 個幣）給出了時間線：10/25 10:23～10:27 四次開頁，每次都在「新聞元件」步驟之後、心跳同時停止（差 0 秒）；正常模式在開頁 1 秒內卡死（開頁軌跡停在「現貨價/幣種表@0.5s」），安全模式在開頁完成 +8 秒（資訊卡延後載入的時刻）卡死。兩種模式唯一共同的東西就是四張資訊卡的載入。

把同一批真實新聞（api/news.js 在 GitHub Actions 上抓到的 20 則）用 app.js 同一批函式逐則跑（tools/news_repro.mjs，diag-news 分支），每則 1ms、全部正常——新聞的 JavaScript 不是兇手。剩下的就是「資訊卡 HTML 寫進頁面之後的那一格繪製」：樣式／版面計算發生在步驟標記之後的下一個畫格，卡在那裡時最後一個標記正好就是「新聞元件」。沙盒的 Chromium 141 畫得出來，不代表 Chrome 155 畫得出來。

### 這一版

1. **繪製麵包屑** `_paintMark`：資訊卡、新聞卡、首頁各寫「繪製中」（rAF）與「已繪製」（畫格提交後）。下次卡死若最後一步是「○○ 繪製中」，就是版面計算，不是 JavaScript。
2. **連續卡死自動隔離**：連續兩次「心跳與步驟同時停」→ 本次自動停用四張資訊卡（卡片位置顯示說明與「重新啟用」）。若這樣就不再卡，兇手確定是資訊卡的繪製。`?nocards=1`／`?nocards=0` 手動開關、`?nonews=1` 只停新聞卡；存活 3 分鐘計數歸零。
3. 新聞逐則麵包屑「新聞處理 i/n 標題」、「新聞元件 渲染」、「資金流動事件卡」、「新聞元件 完成」；新聞標題／摘要／來源進 innerHTML 前一律跳脫（伺服器端去標籤後又把 &lt; 還原了，RSS 內容本來可以原樣注入頁面）；網址只接受 http(s)。

## 三十二、第二台機器的診斷包：卡住的可能是 localStorage 寫入本身（v20260822f，2026-10-27）

第二份診斷包來自另一台機器（12 核／16GB／Chrome 156、全新設定檔 localStorage 僅 9KB、預設幣種 74 個）——資料累積不是原因。這次卡死仍在「新聞元件」之後、心跳同時停，但關鍵在於：v e 在該標記之後立刻排定了 requestAnimationFrame 麵包屑「資訊卡 繪製中」，它**從未寫成**。rAF 回呼在該畫格的版面計算之前執行，若是版面卡住它早該留下紀錄。它沒留下，最合理的解釋是那一次 `localStorage.setItem` 本身沒有回來。與歷史相符：診斷寫入（心跳每 5 秒、逐步驟麵包屑）加入之後使用者回報「更快崩潰」；兩台 Windows 機器、Chrome 155／156 皆然；其他分頁不寫 localStorage 所以沒事。

### 這一版

1. 每次寫入前先以 cookie 記「序號｜步驟」（走另一條 IPC），再寫 localStorage。下次開頁若 cookie 序號 > localStorage 序號 → 紅條「寫入卡住線索」，健康日誌 `ls-hang`；相等 → `ls-ok`（卡點在寫入之後）。
2. `?nols=1`：所有診斷寫入（麵包屑、心跳、健康日誌、長任務、錯誤紀錄、開頁軌跡）改走記憶體＋cookie，不碰 localStorage。主機若用此模式不再卡，即確認；永久修法是把診斷與高頻寫入全部改成 IndexedDB（非同步，不會卡主執行緒）。
3. `?cards=env,er,outlook,news,flow` 只畫指定的卡（逐張二分）；各卡寫入前各有麵包屑。

## 三十三、寫入序號證據與自動二分（v20260822g，2026-10-27）

主機（Chrome 155）v f 的診斷包：卡死步驟「新聞元件 AI寫入」，cookie 序號 13 ＝ localStorage 序號 13（`ls-ok`）——那次寫入是完成的，卡點在寫入之後；localStorage 假設排除。接著新聞的「新聞處理 1/20」從未出現，表示連 /api/news 的回應都還沒處理就卡了；而排定在前的 rAF 麵包屑也沒寫成。剩下的就是「卡片 HTML 寫入之後、下一個畫格的動畫更新／樣式計算」——在 rAF 回呼之前就會執行的那一段。兩台 Windows 機器、Chrome 155／156 皆然；沙盒 Chromium 141 無法重現。資訊卡自動停用的那次開頁活過了 1 分鐘以上（使用者還能操作複製診斷）。

### 自動二分

連續兩次卡死 → 頁面自己做二分：每次開頁只畫一組（全停 → 操作環境 → 反轉 → 大方向 → 新聞 → 資金流動 → 全部），活過 90 秒算通過、下次換下一組；某一組卡死 → 它就是兇手，紅條與健康日誌 `bisect` 顯示結論，之後維持全停讓頁面可用。`?bisect=0` 清除重來；`?cards=`／`?nocards=` 手動指定時不做自動二分。使用者只需要像平常一樣在卡死後重新整理，最多七次就有答案。
